# アタマアソビ ゲームテンプレート

既存ゲーム・古典パズルを短期間でWeb化するための共通テンプレートです。

## 基本方針

新作ごとに大きく変更するのは基本的に次の2ファイルだけです。

1. `js/config.js`
   - ゲーム名
   - SEOタイトル
   - 説明文
   - キーワード
   - 遊び方
   - FAQ
   - アタマアソビURL
   - ランキングON/OFF
2. `js/game.js`
   - ゲーム固有ロジック

その他のファイルは原則として共通化します。

# 新作作成手順

## 1. テンプレートを複製

GitHubでこのリポジトリをTemplate repositoryに設定し、
新作ごとに「Use this template」で新しいリポジトリを作成します。

例:

```text
atamaasobi-game-template
↓
hakoiri-musume
```

## 2. `js/config.js` を変更

最低限ここを変更します。

```js
id: "hakoiri-musume",
title: "箱入り娘",
seoTitle: "箱入り娘｜無料で遊べるスライドパズル",
description: "箱入り娘を無料で遊べるブラウザゲーム。スマホ・PC対応、インストール不要です。",
keywords: [
  "箱入り娘",
  "箱入り娘 パズル",
  "箱入り娘 ゲーム",
  "箱入り娘 無料"
],
canonicalUrl: "https://公開URL/",
portalUrl: "https://アタマアソビのURL/"
```

遊び方・FAQ・ゲーム説明もそのゲーム用に変更してください。

## 3. `js/game.js` をAIに実装させる

AIへの基本指示例:

```text
このアタマアソビ用テンプレートを維持したまま、
js/game.js を中心に「箱入り娘」を実装してください。

共通UI、SEO、ランキング、FAQ、アタマアソビへのリンクは壊さないでください。
スマホ操作を最優先し、タップ・ドラッグの両方で快適に遊べるようにしてください。

終了時は AtamaUI.showResult() を使ってください。
リセットは AtamaGame.restart() で動作するようにしてください。
```

# 共通API

## スコア更新

```js
AtamaUI.setScore(1200);
```

## 時間表示

```js
AtamaUI.setTime("01:23");
```

## リザルト表示

```js
AtamaUI.showResult({
  title: "クリア！",
  stats: [
    { label: "手数", value: 81 },
    { label: "タイム", value: "02:15" }
  ],
  rankingScore: 81
});
```

ランキングを使わない場合は `rankingScore` を省略できます。

# ランキング

`config.js`:

```js
ranking: {
  enabled: true,
  supabaseUrl: "https://YOUR_PROJECT.supabase.co",
  supabaseAnonKey: "YOUR_KEY",
  table: "hakoiri_scores",
  sortDirection: "asc",
  secondaryColumn: "time_ms",
  secondaryDirection: "asc",
  limit: 10
}
```

### 推奨テーブル例

```sql
create table public.hakoiri_scores (
  id bigint generated by default as identity primary key,
  name text not null,
  score numeric not null,
  time_ms bigint,
  created_at timestamptz default now()
);
```

公開サイトから書き込む場合はSupabase側のRLS / Policy設定が必要です。

# AdSense

`index.html` 内のコメント位置に自分のAdSenseコードを貼ります。

そのうえで:

```js
ads: {
  enabled: true
}
```

に変更すると共通広告枠が表示されます。

実際の広告ユニットを使う場合は `#ad-slot` の中身を広告コードへ差し替えてください。

# SEO公開前チェック

- [ ] `<title>` がゲーム名 + 検索意図になっている
- [ ] description に「無料」「ブラウザ」「インストール不要」等を自然に入れた
- [ ] ゲーム固有の遊び方がある
- [ ] FAQがゲーム固有の内容になっている
- [ ] `canonicalUrl` を本番URLへ変更
- [ ] `robots.txt` のドメインを変更
- [ ] `sitemap.xml` のドメインを変更
- [ ] OGP画像をゲーム専用画像へ変更
- [ ] faviconをゲーム専用アイコンへ変更
- [ ] スマホで実際に最後までプレイ確認
- [ ] 横スクロールが出ない
- [ ] タップ/ドラッグがスクロールと競合しない
- [ ] リザルトから再プレイできる
- [ ] アタマアソビへのリンクが正しい

# Vercelで公開

1. GitHubへ新作リポジトリをpush
2. Vercelを開く
3. Add New → Project
4. GitHubリポジトリを選択
5. Framework Presetは `Other`
6. Build Command不要
7. Output Directory不要
8. Deploy

静的HTMLなので基本的にビルド処理は不要です。

# Netlifyで公開

GitHub連携の場合:

1. Add new site
2. Import an existing project
3. GitHubを選択
4. 対象リポジトリを選択
5. Build command空欄
6. Publish directory `.`

---

# Google Search Console

公開後:

1. Search ConsoleでURLプレフィックス登録
2. 所有権確認
3. `sitemap.xml` を送信
4. URL検査
5. インデックス登録をリクエスト
6. 2〜4週間はクエリ・表示回数・CTR・順位を観察

初期段階では、ゲームを過剰に作り込むより、
「Googleにどんなクエリで表示されるか」を確認してから追加投資します。

# アタマアソビ本体への追加

アタマアソビ側を `games.js` 方式にしている場合、公開後は1件追加するだけにします。

例:

```js
{
  title: "箱入り娘",
  url: "https://hakoiri-musume.vercel.app/",
  image: "./assets/hakoiri-musume.webp",
  description: "定番スライドパズルを無料でプレイ",
  category: "パズル",
  playTime: "1〜5分"
}
```

# AI量産時のルール

短期間で多数公開する場合でも、以下は各ゲームで必ず固有化します。

- 本当に遊べるゲーム本体
- そのゲーム固有の説明
- そのゲーム固有のルール
- FAQ
- タイトル・description
- OGP / favicon
- スマホ操作確認

ゲーム名だけ差し替えた薄いページを大量に作るのではなく、
各ページに「そのゲームを遊びたい人が満足できる価値」を持たせます。
